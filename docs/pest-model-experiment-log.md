### 설정
- 데이터: Mendeley PDDICP. 과실 3클래스만 쓴다: 정상(healthy) / 세균구멍병(shot hole) / 잿빛무늬병(brown rot)
  - 제외: bacterial spot (영양결핍 사진 복사본, 라벨 오류), 잎 클래스
- 저장 위치: `~/peachscope-data` (저장소 밖. 사진은 git에 올리지 않음)
- 환경: Apple M4, PyTorch MPS

### 코드 (`pest_model/`)
| 파일 | 역할 |
|---|---|
| `run_all.sh` | 전체 자동 실행. 이미 끝난 단계(가상환경, 다운로드, 분할)는 건너뜀 |
| `prepare.py` | zip에서 3클래스 추출 → 짧은 변 288px로 축소 → 같은/거의 같은 사진(dHash 거리 ≤ 6)을 한 묶음으로 → 클래스별 묶음 단위 8:1:1 분할 (seed 42) |
| `bias_check.py` | 16×16 축소 사진, 색 히스토그램만으로 로지스틱 회귀 → 병반 없이도 맞히는지 확인 |
| `train.py` | timm 사전학습 모델 4종 미세조정. 좌우 뒤집기만 사용, val/test 증강 없음, 클래스 가중 손실, val macro-F1 최고 epoch로 test 1회 평가 |
| `report.py` | 결과표 `pest_model/results/results.md` 생성 |
| `gradcam.py` | 모델이 사진의 어디를 보고 판단했는지 열지도로 표시 |
| `cv.py` | test를 뺀 90%로 5-fold 교차검증 → 평균 ± 표준편차 |

비교 모델 (크기·구조가 다른 4종):
- MobileNetV3-Large: 5.5M, 모바일용
- EfficientNet-B0: 5.3M
- ResNet-50: 25.6M, 기본 기준선
- ConvNeXt-Tiny: 28.6M, 최신 CNN

### 실험 1 결론

1. **동작하는 베이스라인이 나왔다.** 5-fold 교차검증 기준 macro-F1 **0.85**, 정확도 **0.95**다 (ConvNeXt-Tiny, ResNet-50).
2. **정상과 세균구멍병은 잘 된다** (F1 0.96~0.98). 다만 병반이 안 보이는 입력으로도 정확도 0.68~0.74가 나오므로, 이 점수에는 촬영 거리·구도 단서가 섞여 있다.
3. **잿빛무늬병은 안 된다** (F1 0.63). 학습 사진이 40장뿐이고, 절반 가까이를 세균구멍병이나 정상으로 착각한다.
4. **1회 분할 점수는 과대평가된다.** 교차검증보다 0.03~0.1 높았다. 발표 때는 교차검증 평균 ± 표준편차를 보고한다.
5. 앱 탑재용 후보는 모델 크기를 고려해 정한다.
   - 서버에서 돌리면: ConvNeXt-Tiny 또는 ResNet-50 (약 25M 파라미터)
   - 폰에서 돌리면: MobileNetV3 (4M 파라미터, macro-F1 0.81, 0.05 손해)

- **2-B 모델이 Islamia 원래 라벨과 크게 어긋난다.** oracle 혼동행렬에서 Islamia "세균구멍병" 175개 중 142개를 잿빛무늬병, 28개를 정상으로 판정했다. 라벨 점검에서 본 것과 같은 방향이다. Islamia의 세균구멍병 라벨 상당수(`bad-` 출처 등)는 일반 부패과를 붙인 것이라 실제로는 잿빛무늬병처럼 보인다. 따라서 이 표의 2-B 점수는 B 모델이 틀렸다는 뜻이 아니라 **정답이 의심스럽다**는 뜻이다. 어느 쪽이 맞는지는 재라벨한 test로 판정한다.
- 반대로 실험 2 모델이 Islamia test에서 높은 점수를 받는 것은 **같은 노이즈를 학습했기 때문**일 수 있다. 이 점수도 재라벨 전까지는 믿을 수 없다.
- **1단계와 2단계는 이 test에서 사실상 같다** (끝단 macro-F1 0.632 vs 0.631, 사진 단위 0.85 vs 0.87).
  - 1단계는 과실을 덜 찾지만(재현율 0.69 vs 0.76) 찾은 과실은 잘 맞힌다(짝지은 분류 0.93). 오탐도 조금 적다(정밀도 0.64 vs 0.60).
  - 두 방식의 차이가 작은 것은 끝단 점수를 정답 박스 품질(병반 단위 박스, 라벨 빠진 과실)이 누르고 있기 때문일 수 있다.
  - 그래서 어느 구조를 고를지는 재라벨한 test로 다시 재고 정한다. 2단계의 장점은 분류기만 따로 바꿀 수 있다는 것이다. 예를 들어 깨끗한 데이터로 학습한 B 분류기를 쓰거나, 국내 사진으로 미세조정한 분류기를 끼울 수 있다. 1단계의 장점은 모델 하나로 끝나서 앱에 넣기 쉽다는 것이다.

  - 세균구멍병 5장 중 4장을 둘 다 검은별무늬병으로 판정했다. 잎 증상 질문 규칙(대응방안 JSON의 disambiguation)이 필요한 경계다.
  - 검은별무늬병은 충해과 3, 정상 2, 세균구멍병 1로 흩어졌다(데이터 37개).
  - 노린재·바이로이드·멸구 5장은 학습 클래스에 없는 병해충이다(정상으로 판정 3).

**해석**
- **크기 차이는 작다.** NCPMS에서 288이 병명 1장, 부패병 그룹 3장, 이상 검출 1장을 더 맞혔다. 91장 평가에서 이 정도는 우연 범위다. val은 224가 높지만(0.935 vs 0.917), 헷갈리는 크롭이 빠진 쉬운 val이라 판단 근거로 약하다.
- **224의 이점은 속도다.** CPU 추론은 약 25% 빠르고(202 vs 269 ms), 학습은 절반 시간이다. 앱에서 사진 한 장의 과실 몇 개를 판정하는 용도라면 두 크기 모두 서버 부담은 크지 않다.
- **두 모델 모두 이전 실험 3 예비(53/91)보다 낮다.** 차이의 대부분은 세균구멍병(5/5 → 1/5)이다. 이번 학습은 검수 대상 442개(헷갈리는 사례)를 뺐다. 그 바람에 NCPMS 같은 어려운 사진에 필요한 경계 사례를 덜 배운 것으로 보인다. 확정 라벨만 쓰는 것은 대안이 아니고, **팀 검수로 검수 대상을 살려 넣어야 한다**.
- val 점수(0.92~0.94)와 NCPMS 점수(약 49%) 사이의 큰 차이는 학습 분포(zeerox·Islamia 사진)와 한국 과원 사진 사이의 차이를 다시 보여 준다.

**결정(잠정)**: 입력 크기는 288을 유지한다. 성능은 사실상 같고, 288은 지금 파이프라인과 전달서 기준이며 부패병 그룹에서 조금 낫다. 추론 속도가 문제가 되면 224로 바꿔도 손해가 거의 없다. 팀 검수 뒤 정식 재학습에서 한 번 더 확인한다.

**다음**: 팀 검수 결과를 반영한 라벨로 재학습한다. 이때 사진당 크롭 상한을 검토하고, 이번 결과를 기준선으로 쓴다(NCPMS 병명 45/91, 세균구멍병 1/5).

## 손실 함수 비교: 클래스 가중치 CE vs focal loss (2026-11-24)

**목적**: 클래스 불균형(정상 2,102 vs 탄저병 32)에 대한 대응을 비교한다. PDID 논문(Yao et al. 2022)에서는 focal loss가 모든 비교에서 CE보다 좋았다.

**방법**: 실험 4와 같은 데이터·설정에서 손실만 바꿨다(`train_exp4.py --loss`, `results/run_loss_cmp.sh`).
- 기준: 클래스 가중치 CE (실험 4)
- A `focal_w`: 클래스 가중치 + focal loss, γ=2 (`results/exp4_focal_w`)
- B `focal`: 가중치 없는 focal loss, γ=2 (`results/exp4_focal`)

**결과** (NCPMS 91장)

| | 기준 CE+가중치 | A focal+가중치 | B focal |
|---|---|---|---|
| 최고 epoch / 실행 | 8 / 11 | 2 / 5 | 2 / 5 |
| val macro-F1 | **0.865** | 0.854 | 0.847 |
| 병명 정답 | **48/91** | 44/91 | 43/91 |
| 이상 검출 | 85/91 | **86/91** | 83/91 |
| 부패병 그룹 | **49/61** | 45/61 | 48/61 |
| 부패병 아닌 것을 부패병으로 | **6/30** | 8/30 | 9/30 |
| 반점병 | **11/17** | 10/17 | **11/17** |
| 잿빛무늬병 | **25/31** | 21/31 | 24/31 |
| 탄저병 | 7/19 | **9/19** | 5/19 |
| 충해과 | 3/8 | **4/8** | 3/8 |
| 기타 | **2/16** | 0/16 | 0/16 |

- McNemar(기준 대비, 사진별 정답):
  - A: 기준만 맞힘 11장, A만 맞힘 7장, p = 0.48
  - B: 기준만 맞힘 9장, B만 맞힘 4장, p = 0.27
  - 둘 다 통계적으로 의미 있는 차이는 아니다.

**해석**
- focal loss는 이번 데이터에서 이득이 없었다. 수치는 기준(클래스 가중치 CE)이 조금 낫지만 우연 범위다. **기준 손실을 유지한다.**
- A와 B는 모두 2 epoch째 val 점수가 가장 높았고, 그 뒤 val이 흔들려(0.70~0.85) 5 epoch에서 조기 종료됐다. 충분히 학습되기 전 모델이 선택된 셈이다. focal loss는 학습률이 높은 초반에 val이 불안정했다. γ나 학습률을 바꾸거나 patience를 늘리면 결과가 달라질 수 있다.
- A는 탄저병(9/19)과 충해과(4/8)가 조금 늘었고, 잿빛무늬병(21/31)은 줄었다. 소수 클래스 쪽으로 판정이 옮겨 간 정도다.
- val의 탄저병은 7개, 기타는 9개뿐이라 val macro-F1이 몇 장에 크게 흔들린다. 조기 종료 기준으로 쓰기에 val이 작다. 팀 검수 뒤 재학습할 때는 patience를 늘리거나(예: 5) 최소 epoch를 둔다.

  - 증강에서 구멍·상처 형태를 덜 망가뜨리는 설정(자르기 범위 0.85~1, 색 변화 제거 등)을 시험한다.
  - base·지식 손실만·D를 seed 2~3개로 반복해 차이가 우연인지 확인한다.

- **지식 손실만이 가장 안정적이다.** NCPMS 범위가 가장 좁고(67~70), 반점병도 13~16으로 유지된다. 다만 평균은 D와 사실상 같다.

- **배포 모델은 D seed 42를 유지한다.** 바꿔도 기대 성능이 오르지 않는다. 다만 인수인계 문서의 성능 수치(81%)는 seed 평균(약 77%)을 함께 적어야 한다.
- **다음 후보**:
