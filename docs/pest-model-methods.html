1. 전체 흐름

목표는 복숭아 과실 사진에서 정상 / 세균구멍병(shot hole) / 잿빛무늬병(brown rot)을 판정하는 것입니다. 두 가지 구조를 만들어 비교했습니다.

3. 전처리

3-1. 공통: 중복 사진 묶기와 묶음 단위 분할

  • EXIF 회전 보정: ImageOps.exif_transpose로 촬영 방향대로 세운 뒤 RGB로 변환
  • dHash 지각 해시: 흑백 17×16으로 줄이고 이웃 픽셀 밝기를 비교해 256비트 지문을 만듦. 해밍 거리가 작으면 같은 사진 또는 증강본으로 판단
    • 실험 1: 거리 ≤ 6
    • 실험 2: 거리 ≤ 10 (Roboflow 증강본까지 잡기 위해 기준을 넓힘)
  • Union-Find 묶기: 해시가 가까운 사진, Roboflow 원본 이름(이름.rf.해시의 앞부분)이 같은 사진을 한 묶음으로 합침
  • 묶음 단위 층화 분할 (seed 42): 같은 묶음은 반드시 같은 쪽(train/val/test)에 들어감 → 같은 사진의 변형이 train과 test에 갈라져 점수가 부풀려지는 것(누수)을 막음

3-2. 실험 1 (PDDICP 사진 전체 분류)

단계내용
추출zip에서 과실 3클래스만 추출: 정상 353, 세균구멍병 540, 잿빛무늬병 49
축소 저장짧은 변 288px로 줄임 (Bicubic)
분할클래스별 묶음 단위 8 : 1 : 1 (train / val / test)
교차검증test를 뺀 90%로 5-fold 교차검증 → 평균 ± 표준편차로 보고

3-3. 실험 2 (Islamia: 과실 잘라서 분류)

발견한 문제 · Islamia 원래 분할에서는 원본 852개의 증강본이 train/valid/test에 섞여 있었습니다. 공개된 mAP 94.3%가 부풀려진 이유입니다. 그래서 위의 묶음 단위 방식으로 다시 나눴습니다.
단계내용
중복 점검Islamia 내부, Islamia–PDDICP 사이 dHash 거리 계산 (메모리 절약을 위해 256장씩 나눠 계산). PDDICP와 겹치는 묶음 19개 표시
재분할원본 1,488묶음을 70 / 15 / 15로 분할. 대표 클래스 우선순위는 잿빛무늬병 > 세균구멍병 > 정상. valid/test는 묶음당 1장만 남겨 증강본 중복 제거 → train 2,717장, valid 223장, test 223장
과실 자르기정답 박스를 정사각형으로 넓히고 사방 10% 여백 → 288×288 (Bicubic). 모든 과실이 같은 크기가 되어 촬영 거리·구도 단서가 사라짐. 사진 밖으로 나간 부분은 검은색
작은 박스 제외짧은 변 48px 미만은 병반이 안 보여 학습에서 제외 (461개). 시스템 평가 때는 제외하지 않음
결과과실 4,244개. train: 정상 762 / 세균구멍병 1,961 / 잿빛무늬병 935

3-4. 실험 2-B (믿을 만한 라벨만 모은 데이터)

라벨을 점검해 보니 Islamia에는 사진 하나의 라벨을 모든 박스에 붙인 경우, bad- 출처의 일반 부패과를 세균구멍병으로 붙인 경우, PDDICP 세균구멍병 41장을 잿빛무늬병으로 붙인 경우가 있었습니다. 그래서 라벨이 믿을 만한 부분만 모았습니다.

단계내용
포함zeerox 전체(정상·세균구멍병·잿빛무늬병) + Islamia의 GOOD- 정상 + 숫자형 파일명의 잿빛무늬병
제외PDDICP와 겹치는 Islamia 묶음 (zeerox에 이미 들어 있음)
다각형 → 박스zeerox의 다각형 라벨(2,488줄)을 꼭짓점을 모두 감싸는 사각형으로 변환
분할Islamia는 3-3의 분할을 그대로 따름. zeerox는 따로 묶고, Islamia와 겹치면 그 분할을 따르게 함(test > valid > train 우선). 나머지는 70 / 15 / 15
결과과실 4,464개 (train 3,310 / val 600 / test 554)

5. 평가와 점검 방법

5-1. 지표

  • macro-F1: 클래스별 F1의 단순 평균. 정상이 많은 데이터에서도 잿빛무늬병 성능이 똑같은 무게로 반영됨 (정확도 대신 주 지표로 사용)
  • mAP50 / mAP50-95: YOLO 탐지 성능. IoU 0.5 기준 / 0.5~0.95 평균

5-2. 시스템 전체 평가 (eval_pipeline.py)

2단계, 1단계, oracle(정답 박스로 자른 경우, 분류기만의 상한)을 같은 방식으로 채점했습니다.

  1. 과실 짝짓기: 예측 박스를 신뢰도 높은 순으로, IoU ≥ 0.5인 정답 박스와 1:1로 짝지음(탐욕적 매칭) → 탐지 재현율·정밀도
  2. 짝지은 과실 분류: 탐지가 맞은 과실만 놓고 혼동행렬, macro-F1
  3. 끝단(end-to-end) F1: 놓친 과실은 FN, 짝 없는 예측은 FP, 클래스가 틀린 경우는 FN과 FP 둘 다로 셈
  4. 사진 단위 F1: “이 사진에 X병 과실이 있나”를 클래스별로 판정. 앱에서 사진 한 장으로 진단하는 상황에 가장 가까움

5-3. 편향·지름길 점검

방법무엇을 보나
저해상도 기준선 (bias_check.py)16×16으로 줄인 사진, HSV 색 히스토그램만 넣은 로지스틱 회귀(표준화, L2)가 얼마나 맞히는지 → 병반이 안 보여도 맞힌다면 배경·구도·색 같은 지름길이 있다는 뜻
출처 지름길 (eval_by_source.py)2-B 데이터는 출처마다 클래스 구성이 다름. CNN 재현율을 (출처, 정답)별로 나눠 보고, 16×16 입력으로 출처를 맞히는 로지스틱 회귀로 출처 구별이 얼마나 쉬운지 확인
Grad-CAM (gradcam.py)마지막 합성곱 층의 기울기로 모델이 사진의 어디를 보고 판단했는지 열지도로 표시
